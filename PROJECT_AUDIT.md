# Together — Project Technical Audit

Generated by inspecting the actual current source (frontend `src/`, backend `backend/`, migrations, and route wiring). Statements are **confirmed facts** unless prefixed with **(Recommendation)** or **(Inconsistency)**. No application code was modified to produce this document. No secret values are printed.

---

## 1. Project overview

**Purpose.** Together is a social network ("Different people. One world.") — a feed of posts with likes/comments/bookmarks, follow/block social graph, notifications, private 1‑to‑1 messaging with realtime delivery, and automatic message/post/comment translation.

**Current architecture.**
- **Frontend:** Next.js 15.5.25 (App Router, React 19), TypeScript, Tailwind CSS v4, `lucide-react` icons. Client talks to the backend over HTTP with `credentials: "include"`.
- **Backend:** Go (module `together/backend`, go 1.27), stdlib `net/http` with the Go 1.22 method+wildcard mux. Layered `internal/` packages (repository pattern). One external web dep: `github.com/gorilla/websocket`.
- **Database:** PostgreSQL 17 (pgx/v5 + pgxpool). Plain SQL migrations applied manually.
- **Storage:** AWS SDK v2 S3-compatible (S3/Cloudflare R2) via presigned upload URLs.
- **Realtime:** WebSocket hub (gorilla/websocket) — connection tracking + per-user push.
- **Translation:** provider-agnostic `translation.Service`; real Google Cloud Translation v2 provider + offline stub.

Separate origins in dev: frontend `http://localhost:3000`, backend `http://localhost:8080`.

## 3. Frontend architecture

- **Root layout** `src/app/layout.tsx`: `<html><body>` + `globals.css` + `<AuthProvider>`. No AppShell (moved out).
- **`(app)` layout** `src/app/(app)/layout.tsx`: **client** auth gate. `useAuth()` + `useRouter()`; redirects to `/login` only when `status === "unauthenticated"`; shows a Together-branded loader (globe `animate-pulse`) while `loading`/redirecting; renders `<AppShell>` when authenticated.
- **AppShell** `src/components/layout/AppShell.tsx`: Header + Sidebar + `<main>` + RightSidebar.
- **AuthProvider** `src/lib/auth-context.tsx`: `{status: loading|authenticated|unauthenticated, user, refresh}`. `load()` calls `getMe()`; **401 → unauthenticated**; **network/5xx → transient, retried with backoff `[500,1000,2000,4000]ms`, does not sign out** (recent fix).
- **FeedProvider** `src/lib/feed-context.tsx`: owns `posts`, `status`, `nextCursor`, `loadingMore`; `reload`, `loadMore`, `prependPost`. Provided in Home page around Composer + Feed.
- **Major components:** `Header` (server) + `HeaderUser` (client, real `useAuth` name/initial) + `NotificationsBell` (client, real notifications), `Sidebar` (client, `usePathname` active state), `RightSidebar`/`SuggestedPeople`/`WorldMapCard` (mock), `Composer` (real create), `Feed`/`PostCard` (real feed + like/save/comment), `StoriesRow` (mock), `ConversationThread` (real message history, no send).
- **State ownership:** feed state in FeedProvider; auth state in AuthProvider; conversation list + selection in messages page; thread messages inside `ConversationThread` (keyed remount per conversation).
- **API client** `src/lib/api.ts`: base URL `NEXT_PUBLIC_API_BASE_URL` (default `http://localhost:8080`); `apiFetch<T>` with `credentials: "include"`, JSON handling, `ApiError{status,message}`, 204/no-JSON handling, abort. `map-post.ts` adapts `ApiPost → Post` view model.

## 4. Backend architecture

Packages in `backend/internal/`: `auth, block, bookmark, comment, commentservice, config, conversation, db, follow, followservice, like, likeservice, media, notification, post, postservice, ratelimit, realtime, server, session, storage, translation, user`.

- **auth** (`internal/auth`, `server/auth.go`): bcrypt password hashing/policy; register (now also creates a session — auto-login), login, logout, `/auth/me`; session token generation + SHA-256 hashing; `together_session` cookie.
- **users/profiles** (`user`, `server/profile.go`, `server/users.go`): `User` model incl. `PreferredLanguage`, `AutoTranslateEnabled`; profile GET/PATCH; public profile by username.
- **follows/blocks** (`follow`, `block`): follow graph + block graph; block hides both directions.
- **posts** (`post`, `postservice`): create (with media, transactional), read (visibility public/private/followers + block), edit, delete, feed (following/own timeline).
- **likes** (`like`, `likeservice`): like/unlike; `likeservice` creates like + `post_like` notification atomically.
- **comments** (`comment`, `commentservice`): create/list/edit/delete; `commentservice` creates comment + `post_comment` notification atomically.
- **bookmarks** (`bookmark`): save/unsave/list.
- **notifications** (`notification`): create/list (keyset)/unread-count/mark-read/mark-all-read; types `follow`, `post_like`, `post_comment`.
- **conversations/messages** (`conversation`): open private conversation (canonical pair), create message (validates + resolves recipient in tx), list messages (keyset), list conversations (with unread count, single query + lateral), mark read.
- **WebSocket realtime** (`realtime`, `server/websocket.go`): concurrency-safe `Hub` (per-user client sets, non-blocking send, slow-client drop), ping/pong, limits.
- **translation** (`translation`): `Service` interface; `StubService`; Google v2 provider (`X-Goog-Api-Key` header, timeout, safe errors). Applied to messages, posts, comments per viewer/recipient prefs.
- **media/storage** (`media`, `storage`): media rows + S3 presigned upload URLs; confirm flow; public URL via `MEDIA_PUBLIC_BASE_URL`.
- **rate limiting** (`ratelimit`, `server/middleware.go`): in-memory limiter; register 5/10min/IP, login 10/10min/IP.
- **CSRF** (`server/middleware.go` `csrfProtect`): strict `Origin == cfg.AppOrigin` on state-changing methods.
- **CORS** (`server/server.go` `withCORS`): allows only `cfg.AppOrigin`, `Access-Control-Allow-Credentials: true`, handles OPTIONS preflight.

**Major tables:** `users` (+ `preferred_language`, `auto_translate_enabled`), `sessions`, `follows`, `blocks`, `posts`, `post_likes`, `post_comments`, `post_media`, `post_bookmarks`, `notifications`, `conversations`, `messages`, `conversation_participants` (13 public tables).

**Key relationships/constraints:**
- `sessions.token_hash` UNIQUE; `expires_at` indexed; lookup requires `expires_at > now()`.
- `follows`/`blocks`: composite PK on the pair; no self-follow check.
- `conversations`: canonical ordered pair `user_low < user_high` (CHECK) + UNIQUE `(user_low,user_high)` → no duplicate private pairs.
- `messages`: FK conversation/sender CASCADE; content non-empty CHECK; index `(conversation_id, created_at DESC, id DESC)`.
- `conversation_participants`: PK `(conversation_id,user_id)`; `last_read_message_id`, `last_read_at` (read-state).
- `notifications`: type CHECK (`follow`/`post_like`/`post_comment`); index `(user_id, created_at DESC, id DESC)` + partial unread index.
- `post_media`: unique storage_key.

**Session storage:** DB-backed (`sessions` table); only SHA-256 hash stored, never the raw token. **Unread/read state:** per-participant `conversation_participants.last_read_at`; unread computed in the conversation-list query; notifications track `read_at`.

## 7. Authentication status

- **Registration:** `POST /auth/register` validates, hashes password, creates user, **and now creates a session + sets cookie (auto-login)**. Returns 201 with the user.
- **Login:** `POST /auth/login` verifies bcrypt, creates DB session, sets cookie. Generic 401 message for all auth failures (`invalid email or password`) — reused by `unauthorized()` for every 401 including `/me`, `/feed`.
- **Sessions:** DB-backed, 7-day TTL; raw token in cookie, SHA-256 hash in DB; active lookup requires `expires_at > now()`. Survives backend restarts (persisted in Postgres, deterministic hash).
- **Cookie behavior:** `together_session`, `Max-Age=604800` + `Expires` (persistent, ~7d), `HttpOnly`, `SameSite=Lax`, `Secure` only in production, `Path=/`, host-only for `localhost`.
- **Auth persistence:** cookie + DB both 7 days; frontend `AuthProvider` no longer signs out on transient `/me` failures (retries; only real 401 → unauthenticated) — recent fix.
- **Route protection:** `(app)` group layout gate redirects unauthenticated users to `/login`; `(auth)/login` is public.
- **Known remaining auth gaps:** no logout UI (backend endpoint exists, no FE button); no profile/settings pages; **(Inconsistency)** the generic 401 message text ("invalid email or password") is returned even for `/me`/`/feed`, which is intentional-but-confusing; opening `127.0.0.1:3000` instead of `localhost:3000` would not send the host-only cookie (dev servers use `localhost`).

## 9. Realtime

- **Architecture:** `realtime.Hub` tracks `map[userID]→set of *Client`; each client has a buffered send channel (32); `SendToUser` is non-blocking and drops/retires slow clients. `server/websocket.go`: `GET /api/v1/ws` authenticates (session), enforces `Origin == AppOrigin`, upgrades (gorilla), read pump (read limit 4096, pong-refreshed 60s deadline, inbound frames discarded), write pump (ping every 30s, write deadline 10s).
- **Events implemented:** exactly one — `{"type":"message.created","data":<message>}`, published to the **recipient only** after a message is persisted (`publishMessageCreated`), translated for the recipient's prefs. Non-blocking; delivery failure never fails the request.
- **Frontend integration:** **none** — the client never opens `/api/v1/ws` and has no event handling. So messages do not appear live; only on reload/reselect.
- **Limitations:** inbound WS messages are discarded (no client→server protocol); only `message.created` exists (no typing/read/notification events); no reconnect/backoff client logic (none exists yet); events are per-recipient only.

## 10. Translation

- **Google integration:** `translation.NewService("google", apiKey, endpoint)` → Google Cloud Translation **Basic v2** (`POST` JSON `{q,target,format:"text",source?}`, API key via `X-Goog-Api-Key` header only, per-call timeout, opaque `ErrProviderRequestFailed`). Verified working live earlier (uz→ru). Default provider is `stub` (offline echo) unless `TRANSLATION_PROVIDER=google` + `TRANSLATION_API_KEY` set (validated at `config.Load`).
- **Supported content types:** message history (`GET /conversations/{id}/messages`), realtime `message.created` event, post responses (`GET /posts/{id}`, feed, create/edit), comment responses (create/edit/list). Each carries `translatedContent`/`sourceLanguage`/`targetLanguage`; original always preserved.
- **User language preferences:** `users.preferred_language` (nullable) + `auto_translate_enabled` (default false); editable via `PATCH /profile`; validated with `translation.ValidLanguage`.
- **Frontend integration:** **none** — the API returns translation fields, but no UI renders `translatedContent` or lets users toggle `autoTranslateEnabled` / set `preferredLanguage`.
- **Failure behavior:** translation errors are swallowed everywhere — the response/event still returns the original content; never fails a request or realtime delivery.
- **Cost/usage:** real Google calls occur only when the viewer/recipient opted in AND has a preferred language AND content is non-empty; each translated item is one API call per message/post/comment (no batching, no caching). (Recommendation) add caching/batching before enabling broadly.

## 12. Security review (confirmed current state)

- **Sessions:** DB-backed, 7-day expiry, raw token only in HttpOnly cookie, SHA-256 hash in DB, active check on `expires_at`.
- **Password hashing:** bcrypt with length policy (`auth` package); never stored/returned in plaintext; responses exclude `password_hash`.
- **CSRF:** `csrfProtect` requires `Origin == cfg.AppOrigin` on non-safe methods for state-changing routes (login/register are rate-limited, not CSRF-gated).
- **CORS:** `withCORS` reflects only `cfg.AppOrigin`, `Allow-Credentials: true`, handles preflight; foreign origins get no ACAO.
- **Rate limiting:** in-memory per-IP for register/login; **resets on process restart** (not distributed/persistent).
- **Origin checks:** both CSRF and WebSocket upgrade enforce exact `AppOrigin`.
- **WebSocket security:** requires session auth + Origin match before upgrade; read limit + deadlines; per-recipient delivery only.
- **Block/privacy:** post visibility (public/private/followers) enforced server-side; blocks hide content both directions; non-members get 404 (existence hidden) for conversations/comments/likes.
- **Validation:** content-type checks, `DisallowUnknownFields`, length/rune limits (posts/comments/messages), UUID pattern checks, language-code validation.
- **Secret handling:** all secrets via env (`DATABASE_URL`, `TRANSLATION_API_KEY`, storage keys); `.env` not committed; secrets never logged. Backend `go run` does not auto-load `.env` (must be exported into the process env).
- **Known security debt:** rate limiter is in-memory only; `Secure` cookie off in dev (expected); generic-but-misleading 401 message on all endpoints; no CSRF on `/ws` beyond Origin (acceptable); no per-user WS authorization beyond ownership; media client-side validation absent.
